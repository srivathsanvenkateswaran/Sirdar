Sirdar walkthrough

Ten screens, in the order a support engineer meets them. Every page has a guide bar with Back and Next, and a "Show links" box that outlines what you can click: sidebar rows, cards, table rows, tabs and buttons all go to the screen they would open in the app. Ticket SBX-1 is the sandbox ticket; every name is fabricated.

  1. 1New sessionWhere every piece of work starts: paste a ticket or pick one that landed, choose triage, RCA or fix, and start.From the sidebar's New session button, or on first launch.
  2. 2SessionThe harness surface. The agent's transcript on the left, its changes on the right, and the composer at the bottom for answering its question or steering it. Here the run is blocked on a question.From Start on a new session, from a card on the Board, a row in the Register, or a recent session in the sidebar.
  3. 3Change reviewThe full-width review before a fix becomes a branch: keep or drop each hunk, read the checks and what the agent said, then create the branch.From the Changes tab or Create branch on a session.
  4. 4BoardEvery run as a lane by state, and the inbound strip that says which tickets the webhooks started, skipped or rejected.From the sidebar. Click any card to open its session.
  5. 5RegisterEvery run ever, with the day it happened above the table. Read-only: it has no commit action of its own.From the sidebar. Click a row to open that run's session.
  6. 6EvalRun the golden set again and compare the agent's answers with what a person did.From the sidebar. Run suite queues the runs, which then appear on the Board.
  7. 7Settings: MCP serversWhich servers a run gets and which of their tools it may call. Opens as a modal over the session.From the sidebar's Settings row.
  8. 8Settings: Try a toolCall one MCP tool by hand, see the verdict Sirdar's permission rules give it, and read the result.From the Try a tool row in the settings nav.
  9. 9Settings: ProvidersEvery installed coding-agent CLI, its sign-in state, whether it may run a fix, and how its read-only guard works.From the Providers row in the settings nav.
  10. 10LibraryThe component gallery: every piece the screens are built from, at the size it ships at.From the sidebar.

How the screens connect

One rule the mocks obey everywhere: exactly one filled black button per screen, and it is that screen's commit action. Start, Answer, Create branch, Run suite, Call, Save. A read-only screen has none of its own.
