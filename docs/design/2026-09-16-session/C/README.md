## The idea

The session window is an IDE, not a chat: the run is a program you attach to, and the window shows its state, its documents and its log at once. A 60px run header carries the state word, three budget gauges (turns, minutes, cost against the caps in `state.json`), the model and the assignee. The centre is a document area with tabs (Answer, Note, Diff, Bundle) rendered as proper documents with an outline rail, so the conclusion and the ticket read like pages rather than JSON or a chat bubble. Below it a collapsible, resizable console renders `events.jsonl` as a structured log: one line per tool call with time offset, tool, input summary, the model's own one-line description of why, duration, output size and the permission decision; filters, search and a follow-live toggle sit in its header. A 56px activity rail on the left maps the turns as a clickable minimap, and the composer is a single command bar at the very bottom with model, mode and access chips.

## Primary and secondary

Primary is whatever the engineer opened the run for, and it is the document area: the Answer for a finished triage, the Diff for a fix, the question band for a blocked run. The console is secondary but never hidden: it is always at least a header with counts (`22 events · 15 calls · 2 denied · 1 steer`), it is one drag away from any height, and every row is expandable in place. The header gauges and the rail are tertiary, glanceable, and never demand a click. One filled button per screen: the command bar's Send / Answer.

## Long outputs

A tool row is one line; its output is only a size (`17 ln · 1.1 KB`) until expanded. Expanded, the call opens a two-pane box under its row: input JSON with keys and strings coloured, then a metadata list (started, decision and the rule that allowed it, duration, output size), and the output parsed into a table when it has a shape (`file:line:match` for rg, `path | count | bars` for `git log --stat`, numbered lines for Read) with the pane scrolling on its own and a wrap toggle, copy and open-raw in its corner. Nothing is truncated on disk-to-screen; the row is the summary, the pane is the whole thing. The Tools view (S5) is the same log with the `tools` filter and wider columns, so every call's duration, decision and output size are compared in one table.

## Blocked, streaming, finished

Finished: the header badge is `completed` in the triaged hue, the gauges are grey and frozen, follow-live is off, the console ends in a `completed` line naming the note that was written, and the command bar offers a follow-up (`mode resume`). Blocked: the badge is `blocked · waiting on you` in the blocked hue, the rail's last cell is a `?`, the question is pinned as a tinted band at the bottom of the console with the time it has been waiting and numbered options, the cost gauge reads `—` because the provider reports cost only with the result, and the command bar switches to `mode answer` with the button relabelled Answer. Streaming (not drawn, since no sandbox run was captured mid-flight): the badge is `running` in the accent, the gauge fills take the accent, follow-live is on and the console's last row is the live tool call with a running duration; the rail grows a cell per turn.

## What I would cut from today's window

The right pane as a separate column: Note, Bundle, Tools and Changes all become documents or console views, so the window has one document area instead of a transcript column fighting a pane column for width. The transcript's chat framing: turn dividers, avatar-style "you" blocks and per-message bubbles go; the steer is one highlighted log line, the answer is one highlighted log line, and prose is a row kind you can filter to. The banner strip above the transcript ("Tests passed"): checks live in the decision bar of the Diff document and in the console rows that ran them. The composer's tall multi-line card: the command bar is one line until you type into it.

## Honesty notes

- Every string comes from the run directories, `bundle/ticket.json`, `thread.md`, `note.md`, `result.json`, `fix.diff` and `state.json`. Time offsets are from the first event in `events.jsonl`; durations are `tool_finished − tool_started`.
- No run in the sandbox ever blocked on a question (there is no `AskUserQuestion` event anywhere). S2 stages the fix run at 00:13.5, after the pre-fix `go test` failed, with the note's own Proposed fix and Risks paragraphs quoted verbatim as the question and its three alternatives as the options. The cost gauge shows `—` there because the harness only reports cost with the result.
- The Claude runs returned no visible text blocks: the model's prose in this window is its `description` per call, its thinking markers (content empty, signature only, shown as such) and its structured answer lines. Codex runs in the sandbox do carry `assistant_text`; the `prose` filter is for those.
- `ops@sandbox.local` is `Tracker.Assignee` from the ticket; `claude-opus-5` is the model in the events (`state.json` has `Model: ""`).
- The fix run's `review` event records that `ledger_test.go` hunk 0 was dropped; S6 shows it struck through in the outline and counts it in the decision bar.
