Apply a return's quantity to stock once in ApplyMovement

tests 4 run · 3 okfiles ledger.go · ledger_test.godeviation from note nonebranch fix-sbx-1-…

What changed

In the Return case, ApplyMovement added the quantity directly and then again through restock, so a return raised on-hand stock by twice its quantity while the movement report (SumMovements/Delta) counted it once. This change removes the restock call and the restock helper, which had no other caller, and keeps the single direct increment. It also adds TestApplyMovementReturnAddsQuantityOnce to ledger_test.go (Purchase 10, Return 1, then assert CurrentStock == 11 and Reconcile ok). The test failed before the fix with CurrentStock = 12.

Risks

This fixes new returns only. Stock that past returns already inflated stays too high until it is rebuilt from movement history (SumMovements over MovementsFor), and that step is not part of this change. If some other integration still sends a separate "item scanned back in" event that adds stock, returns would still be over-counted in production.
